# Linkora — دليل التشغيل الفعلي

هذا مشروع Vercel حقيقي: صفحات ثابتة + Serverless Functions + قاعدة بيانات Redis (Upstash).
لا حاجة لخادم منفصل — كل شيء يعمل على Vercel مباشرة.

## ما الذي تغيّر عن النسخة السابقة؟

| قبل | الآن |
|---|---|
| بيانات محفوظة في متصفحك فقط (localStorage) | بيانات حقيقية في قاعدة بيانات مشتركة (Redis) |
| "الرابط المختصر" نص فقط، لا يعمل فعليًا | `/l/xxxxx` رابط حقيقي يعمل لأي زائر من أي جهاز |
| مستخدم تجريبي واحد ثابت | تسجيل دخول/حساب حقيقي لكل شخص (كلمة مرور مشفّرة) |
| أي شخص يدخل `#admin` | لوحة المالك محمية، تظهر فقط لبريد `ADMIN_EMAIL` |
| المؤقّت 30 ثانية في المتصفح فقط (يمكن التحايل عليه بسهولة) | الخادم يتحقق فعليًا من مرور الوقت قبل احتساب أي ربح |

## 1) التجهيز قبل الرفع

ثبّت أدوات Vercel محليًا (تحتاج Node.js مثبت على جهازك):
```
npm install -g vercel
```

## 2) الرفع إلى GitHub ثم Vercel

```
cd linkora-app
git init
git add .
git commit -m "Linkora"
```
ارفعه إلى مستودع جديد على GitHub، ثم من [vercel.com/new](https://vercel.com/new) اختر **Import** لهذا المستودع.
(بما أنه لا يستخدم أي إطار عمل، سيتعرف عليه Vercel تلقائيًا كمشروع "Other" — لا حاجة لأي إعداد إضافي.)

## 3) ربط قاعدة البيانات (Upstash Redis)

1. من صفحة مشروعك في Vercel → تبويب **Storage** → **Marketplace Database Integrations**
2. اختر **Upstash for Redis** → **Connect** → أنشئ قاعدة بيانات جديدة (يوجد باقة مجانية)
3. سيتم حقن `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` تلقائيًا في متغيرات البيئة

## 4) متغيرات البيئة المتبقية

من **Settings → Environment Variables** أضف:

- `JWT_SECRET` — نص عشوائي طويل. ولّده محليًا بـ:
  ```
  node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  ```
- `ADMIN_EMAIL` — بريدك الإلكتروني الذي ستسجّل به أول حساب (سيصبح تلقائيًا صاحب صلاحية المالك)

بعد إضافتها، اعمل **Redeploy** حتى تُطبَّق.

## 5) أول تشغيل

1. افتح موقعك المنشور → **إنشاء حساب** بنفس بريد `ADMIN_EMAIL`
2. ستدخل تلقائيًا كمالك للمنصة، وسيظهر لك أيقونة ⚙ بجانب اسمك تفتح **/admin.html**
3. من لوحة المالك اضبط: سعر الإعلان، نسبة تقسيم الأرباح، الحد الأدنى للسحب، مدة كل مرحلة
4. أنشئ رابطًا من لوحة التحكم واضغط "معاينة الزيارة" لتجربة التدفّق الحقيقي بنفسك على `/l/xxxxx`

## ربط شبكات إعلانات حقيقية

⚠️ **ملاحظة مهمة:** شبكات مثل Google AdSense عادة **لا تقبل** هذا النوع من المواقع (تخطي إجباري لعرض إعلان قبل الوصول لمحتوى)، لأن سياساتها تمنع تحفيز/إجبار المستخدم على مشاهدة الإعلانات. الشبكات "المتميزة" الفعلية لهذا النوع من المنصات هي شبكات متخصصة تقبل هذا النموذج تحديدًا، أشهرها:

- **Monetag** (الواجهة الناشرة لشبكة PropellerAds) — لا يوجد حد أدنى للزيارات، موافقة سريعة، سحب من 5$
- **Adsterra** — شبكة كبيرة ومعروفة، تدعم Popunder وSocial Bar وغيرها
- بدائل أخرى: RichAds، Clickadu، HilltopAds

سجّل حسابًا في أيّها كناشر (Publisher)، واحصل على كود الإعلان الخاص بك، ثم الصقه داخل `skip.html` في مكان `<div class="ad-box">` (ابحث عن التعليق الذي يشرح ذلك). لا يمكنني إنشاء هذا الحساب نيابة عنك — يتطلب بريدك وموقعك المباشر للموافقة عليه.

## كيف يعمل السحب فعليًا؟

عند الموافقة على طلب سحب من لوحة المالك، **لا يُرسَل الكريبتو تلقائيًا** — هذا مقصود ومطابق لما تفعله أغلب مواقع هذا النوع فعليًا لتفادي الاحتيال. يجب عليك يدويًا إرسال المبلغ من محفظتك الحقيقية إلى العنوان الظاهر في الطلب بعد الموافقة. إن رغبت لاحقًا بأتمتة الإرسال، يمكن ربط خدمة مثل NOWPayments أو CoinPayments (تتطلب حسابًا وأرصدة حقيقية لديك) — أخبرني إن أردت المساعدة بهذه الخطوة لاحقًا.

## حدود معروفة يجب الانتباه لها

- الحماية من التلاعب بالأرباح أساسية (توقيع + تحقق من الوقت الفعلي + منع إعادة الاستخدام) وتكفي لإطلاق أولي، لكنها ليست حماية كاملة من الروبوتات/المزارع الاحتيالية المنظمة — قد تحتاج لاحقًا CAPTCHA أو حدًا لعدد الزيارات لكل IP.
- لا يوجد حاليًا تحقق من البريد الإلكتروني أو "نسيت كلمة المرور" — يمكن إضافتها لاحقًا (تحتاج خدمة إرسال بريد مثل Resend).
- عند حركة زيارات عالية جدًا في نفس اللحظة على نفس الرابط، هناك احتمال ضئيل لتضارب بسيط في تحديث الرصيد (قراءة/تعديل/حفظ وليس عملية ذرية) — كافٍ لحجم استخدام متوسط.

## التشغيل محليًا للتجربة

```
vercel dev
```
ثم `vercel env pull .env.development.local` لجلب متغيرات البيئة الحقيقية إلى جهازك.
